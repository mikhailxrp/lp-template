# Рабочий процесс (дополняет CLAUDE.md проекта, не заменяет)

- Пользователь управляет процессом сам и хочет понимать, что строится: коротко объясняй «что → зачем», после шага
  перечисляй изменённые файлы и как проверить руками.
- Структурные правки (больше 3 файлов, переименования, новые зависимости) сначала план в 3-6 строк, потом «ок».
- Ручные правки пользователя считаются истиной: перечитывай файл перед правкой, не откатывай.
- После каждого блока запускай `/lp-check`; новые ошибки класса error не оставляй.
- JS-хуки только `data-js`, цвета и тени только через токены, `!important` только с комментарием-причиной.
- Не создавай package.json и сборку на этапе 1. Скрипты проверки запускаются просто `node`.
- Не используй API библиотек по памяти: Context7 или документация, если не уверен.
- Новая библиотека или плагин: сначала список (что делает, чем заменить, размер), потом «ок» пользователя. Скачивай файлы локально в `assets/*/vendor`, без CDN, версию запиши в `.docs/direction.md`, раздел «Библиотеки». Актуальное использование сверяй через Context7.
