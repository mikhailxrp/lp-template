# lp-block

Вход: имя блока, источник (файл/селектор донора или скриншот), расположение (в какую страницу, после какого блока).

1. Прочитай `.docs/direction.md`, блок `:root` в `style.css` и соседние блоки в `index.html`/`style.css`:
   переиспользуй существующие токены и классы, не плоди новые.
2. Кратко скажи: что строишь, какие классы, какие токены, нужен ли JS (`data-js`), что берёшь из донора.
   Если блок затрагивает больше одного файла кроме index.html + style.css (+main.js), дождись «ок».
3. Разметка: `<section class="lp-<block>" id="<block>" aria-labelledby>`, сетка только Bootstrap-классами,
   BEM, маркеры `@wp`/`@wp-repeat` как у соседних блоков, имя в закрывающем маркере = имя файла.
4. CSS и JS: только `var(--lp-*)`, mobile-first, без цветов и размеров литералами. Дубли токенов не создавай:
   если значения нет, предложи новый токен отдельной строкой. Если используешь компоненты/API Bootstrap, Owl Carousel или другой библиотеки — сначала сверь актуальную документацию через Context7 MCP (`resolve-library-id` → `query-docs`), не пиши по памяти.
5. Запусти `/lp-check` (в Codex: `$lp-check`), исправь свои находки. Посмотри блок на 375/768/1440 в браузере (Playwright MCP или встроенный `browser`-субагент) и сравни с донором; если в окружении нет браузерного инструмента, проверь адаптивность в коде и дай пользователю чеклист ручной проверки 375/768/1440.
6. Отчёт: изменённые файлы, как проверить руками, что не сделано.
