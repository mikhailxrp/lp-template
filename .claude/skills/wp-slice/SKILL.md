# wp-slice

Механическая часть посадки. Читает `<!-- @wp: путь.php -->` ... `<!-- /@wp: имя -->` на всех `*.html`
в корне проекта и складывает куски в `.wp-slices/template-parts/...`. Проект и тему не трогает.

Скрипт создаёт **только `template-parts`**. `header.php`, `footer.php`, шаблон страницы и всё вне маркеров
(doctype, `<head>`, skip-link, `<main>`, `<script>`) пишутся руками. Модалки нарезаются, только если у каждой
свой маркер (`CLAUDE.md`, 5.2а): после запуска проверь, что они есть в таблице кусков.

1. `node .claude/skills/wp-slice/wp-slice.mjs` (опция `--out папка`).
2. Покажи таблицу кусков и разделы отчёта:
   - **разный HTML у одной части на разных страницах**: обычно ссылки (`#hero` против `index.html#hero`),
     активный пункт меню, id секции. В WP это превращается в `home_url()` и условия. Предложи решение по каждому.
   - **проблемы с маркерами**: незакрытые, без пары. Сначала поправь маркеры в HTML (с разрешения).
3. Дальше по одной части, с планом и «ок»: скопировать из `.wp-slices` в тему, заменить `assets/...`
   на `get_stylesheet_directory_uri() . '/assets/...'`, ссылки на `home_url()`, динамику (`@wp-repeat`, `@wp-loop`, `the_content()`) на поля/цикл.
   Разметку и классы не менять.
4. Поля Redux и API WordPress: перед написанием обязательно сверь актуальную документацию через Context7 MCP (`resolve-library-id` → `query-docs`), не угадывай. Если Context7 MCP недоступен — проверь официальную документацию через веб-поиск или явно предупреди пользователя о неподтверждённых вызовах.

Вставки `get_template_part()` для вложенных частей скрипт ставит сам. Всё остальное остаётся комментариями-маркерами.
