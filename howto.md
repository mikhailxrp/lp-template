# HOWTO: как пользоваться lp-template

Пользуйтесь только этой папкой. Старые наборы (site-kit, wp-kit, lp-kit) не нужны: всё полезное из них уже внутри.

## 0. Что это и зачем

Папка-шаблон для верстки лендинга (HTML/CSS/JS). Вы копируете её под каждый новый сайт, кладёте макет или скрины, и по шагам просите Claude сверстать блоки. Каждый шаг вы проверяете сами.

| Файл / папка         | Что это                                                                     | Кто трогает              |
| -------------------- | --------------------------------------------------------------------------- | ------------------------ |
| `CLAUDE.md`          | Главные правила проекта (источник истины для Claude Code, Antigravity, Codex)| Вы, редко               |
| `AGENTS.md`          | Единая точка входа для Codex и Antigravity (правила, Context7 MCP, скиллы)  | Никто                    |
| `.claude/rules/`     | Дополнительные правила                                                      | Никто                    |
| `.claude/skills/`    | 5 команд и скрипты: `/lp-block`, `/lp-check`, `/seo-files`, `/seo-audit`, `/wp-slice` | Никто          |
| `.agents/skills/`    | Тонкие обёртки скиллов для Codex и Antigravity (ссылаются на `.claude/skills/`) | Никто                |
| `.docs/direction.md` | Шпаргалка по дизайну (цвета, шрифты, отступы)                               | Пишет агент, читаете вы  |
| `.docs/ref/`         | Сюда кладёте макет или скрины                                               | Вы                       |
| `assets/`            | css, js, шрифты, картинки                                                   | Агент и вы               |
| `index.html`         | Главная страница                                                            | Агент и вы               |
| `START.md`           | Короткая версия: фразы для копирования                                      | Вы                       |

## 1. Подготовка (один раз на проект)

1. Скопируйте папку `lp-template`, назовите по сайту, например `site-ivanov`.
2. Откройте её в VS Code (Файл → Открыть папку).
3. Откройте терминал в VS Code и запустите Claude Code командой `claude`.
4. Положите источник в `.docs/ref/`:
   - готовый макет: всю папку (html, css, js, картинки);
   - скрины: png или jpg.
5. Шрифты макета (woff2) положите в `assets/fonts/`, картинки в `assets/img/`. Если не знаете, где они в макете, попросите Claude: «найди шрифты и картинки макета и скопируй, куда нужно».

## 2. Шаги (каждый шаг = одно сообщение в чат)

Готовые фразы лежат в `START.md`, их можно копировать.

### Шаг 1. Выписать дизайн

Вы просите Claude заполнить `.docs/direction.md`.
Результат: файл с цветами, шрифтами, размерами, отступами, анимациями, порядком секций.
Что делаете вы: открываете файл, читаете. Непонятное спрашиваете у Claude. Неверное правите или просите исправить.
Готово, когда: цвета и шрифты в файле похожи на макет.

### Шаг 2. Библиотеки

Вы просите список библиотек макета (слайдеры, анимации и т.п.) без подключения.
Результат: таблица «что это, зачем, чем заменить».
Что делаете вы: по каждой пишете «оставляем» или «заменяем на ...».
Готово, когда: решение записано в `direction.md`, раздел «Библиотеки».

### Шаг 3. Токены

Claude переносит значения из `direction.md` в `assets/css/style.css` (блок `:root`).
Что делаете вы: открываете `style.css`, сверяете несколько цветов с `direction.md`.

### Шаг 4. Заголовок страницы (`<head>`)

Claude заполняет title, description, подключает шрифты и стили. Тексты даёте вы.

### Шаг 5. Блоки по одному

Команда: `/lp-block hero` (потом `/lp-block преимущества` и т.д.)
К команде добавляете: откуда брать вид (секция макета или скрин) и ваши тексты.
Что делаете вы после каждого блока:

1. Открываете `index.html` в браузере (правая кнопка на файле → Open with Live Server, или двойной клик).
2. Смотрите на ширине телефона и компьютера (F12, значок телефона).
3. Принимаете или пишете правки: «отступ больше», «кнопка не того цвета».
   Не переходите к следующему блоку, пока этот не устраивает.

### Шаг 6. Проверка

Команда: `/lp-check`
Результат: список находок трёх уровней:

- **error**: исправить обязательно;
- **warn**: подумать, чаще всего исправить;
- **info**: на заметку (например, `noindex`, который снимаем перед выкладкой).
  Исправляйте по одному пункту: «исправь первый error». Потом снова `/lp-check`.
  Скрипт может ошибаться. Если пункт кажется странным, спросите Claude: «это реально ошибка?».

### Шаг 6б. SEO и GEO

- `/seo-files https://домен.ru`: создаёт заготовки `sitemap.xml`, `robots.txt`, `llms.txt`. Факты в `llms.txt` (цены, сроки, контакты) заполняете вы или даёте Claude взять их из текста сайта.
- `/seo-audit`: три этапа. Скрипт проверяет форму; Claude читает текст и проверяет смысл; затем придумывает 8-10 вопросов клиента и отвечает на них только по вашему сайту (пробелы = чего не хватает в тексте).
- Результат: таблица «что не так, как исправить, кто решает». Тексты, цены и факты решаете вы, Claude их не придумывает.
- Промпт для аудита без Claude Code (вставить в чат вместе с HTML): `.docs/prompts/seo-geo-audit.md`.

### Шаг 7 (позже). Посадка на WordPress

Когда статика готова: `/wp-slice`. Нарежет страницы на куски для темы. Дальше работаете по плану в чате.

Проще так: у тебя две папки, и ты переносишь вёрстку из первой во вторую.

| Папка   | Что в ней                                      |
| ------- | ---------------------------------------------- |
| Статика | готовая вёрстка, .claude/, CLAUDE.md           |
| Тема    | папка темы WP в OpenServer (пока почти пустая) |

_Что делать, по порядку_

1. В папке статики запусти Claude и напиши /lp-check. Исправь красные error.

2. Там же напиши /wp-slice. В статике появится папка .wp-slices/template-parts/ с готовыми кусками (шапка, подвал, секции). Тема при этом не меняется.

3. Скопируй руками в папку темы:

assets/ из статики (css, js, шрифты, картинки);
.wp-slices/template-parts/ в тему как template-parts/;
.claude/, CLAUDE.md, .agents/ и AGENTS.md, чтобы правила и скиллы работали в теме в Claude Code, Antigravity и Codex.

4. Открой папку темы в VS Code и запусти там Claude. Дальше работаешь только в теме.

5. В теме, по одному файлу, с планом и твоим «ок»:

functions.php: подключение CSS и JS.
header.php и footer.php: каркас страницы.
front-page.php: <main> и вызовы секций.
Каждый кусок из template-parts/: заменить пути и ссылки, подключить поля.

## 3. Что делать, если

| Ситуация                            | Что делать                                                                                                                  |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Не понимаю, что происходит          | Напишите: «объясни простыми словами, что мы сейчас делаем и что дальше»                                                     |
| Claude сделал что-то не то          | Напишите, что именно не так. Если совсем плохо: «верни как было, файл X» (VS Code хранит историю: правая кнопка → Timeline) |
| Новая сессия Claude, забыл контекст | «Прочитай CLAUDE.md и .docs/direction.md, скажи, что уже сделано»                                                           |
| Команда `/lp-block` не находится    | Папки `.claude` и `.agents` должны лежать в корне проекта. В Codex можно вызывать как `$lp-block` (или `/lp-block`). Перезапустите агента |
| `/lp-check` пишет «node не найден»  | Установите Node.js с nodejs.org, перезапустите терминал                                                                     |
| Нужна новая библиотека              | Скажите: «предложи варианты и жди моего решения»                                                                            |
| Макет сложнее, чем мои блоки        | Делайте блоки по одному, начиная с самого простого                                                                          |

## 4. Словарь

- **Токен**: именованное значение (`--lp-color-accent`), чтобы цвет задавался в одном месте.
- **Блок / секция**: кусок страницы (первый экран, цены, отзывы).
- **BEM**: схема имён классов `.lp-hero__title`.
- **Маркер `@wp`**: комментарий в HTML, по которому потом нарезаем страницу на PHP-шаблоны.
- **Stage 1 / Stage 2**: сначала статика, потом посадка на WordPress.
- **Скилл (команда с `/`)**: готовая инструкция для Claude.

## 5. Главное правило

Один шаг, одна проверка вами, потом следующий шаг. Если вы не поняли, что сделал Claude, это повод спросить, а не идти дальше.
